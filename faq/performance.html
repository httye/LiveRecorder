性能问题 ​

关于 LiveRecorder 性能的常见问题。

服务器卡顿 ​

问题描述 ​

启用 LiveRecorder 后，服务器出现卡顿。

可能原因 ​

  1. 录制者数量过多

    • 绑定了太多录制者
    • 每个录制者都会消耗资源

  2. 视觉效果过多

    • 启用了粒子效果
    • 启用了过多发光效果

  3. 日志记录过多

    • 日志保留数量过大
    • 频繁的数据库操作

解决方案 ​

减少录制者数量 ​

bash
# 查看所有录制者
/lr list

# 解绑不需要的录制者
/lr unbind Camera01
/lr unbind Camera02

内存占用过高 ​

问题描述 ​

LiveRecorder 占用过多内存。

可能原因 ​

  1. 日志数据过多

    • 日志保留数量过大
    • 数据库文件过大

  2. 绑定数据过多

    • 保存了过多的历史绑定

解决方案 ​

清理旧日志 ​

yaml
privacy:
  live-logs:
    keep-count: 50         # 减少日志保留数量
1
2
3

重启服务器，插件会自动清理旧日志。

手动清理数据库 ​

bash
# 备份数据库
cp plugins/LiveRecorder/privacy.db plugins/LiveRecorder/privacy.db.backup

# 删除并重建（会丢失所有数据）
rm plugins/LiveRecorder/privacy.db

CPU 占用过高 ​

问题描述 ​

LiveRecorder 占用过多 CPU。

可能原因 ​

  1. 跟随计算过于频繁

    • 每个录制者都在计算跟随
    • 计算过于复杂

  2. 视觉效果渲染

    • 粒子效果渲染
    • 发光效果渲染

解决方案 ​

减少录制者数量 ​

网络延迟 ​

问题描述 ​

录制者与目标之间出现网络延迟。

可能原因 ​

  1. 服务器性能不足

    • 服务器负载过高
    • 网络带宽不足

  2. 录制者网络问题

    • 录制者网络不稳定
    • 录制者延迟过高

最佳实践 ​

性能优化 ​

  1. 限制录制者数量 - 最多 5 个录制者
  2. 关闭不必要的视觉效果 - 禁用粒子效果
  3. 合理的日志保留 - 50-100 条日志
  4. 使用合适的配置 - 避免过高的跟随速度

监控性能 ​

  1. 定期检查服务器 TPS - 使用 /tps 命令
  2. 检查录制者数量 - 使用 /lr list 命令
  3. 检查数据库大小 - 定期检查 privacy.db 文件大小

应急处理 ​

  1. 解绑所有录制者 - 快速释放资源
  2. 重启插件 - 使用 /lr reload 命令
  3. 重启服务器 - 如果问题严重
